## I want to… (routing)

| Goal | Go to |
|------|-------|
| Install / set up Qdrant + Ollama + models | [install.md](install.md), then `carta doctor` |
| Find **structural** doc issues (stale/broken `related:`, homeless/orphaned docs) | `carta scan` (no LLM) or the `/doc-audit` skill → `docs/AUDIT_REPORT.md` |
| Check **embedded-data integrity** (orphaned sidecars, damaged/duplicate points) | `carta audit` / `carta doctor` |
| Diagnose a **retrieval-quality** problem (recall/ranking) | `carta eval` against the eval set (see [../README.md](../README.md) "Retrieval quality") |
| Embed visually-rich PDFs (datasheets, diagrams) | two-pass: `carta embed`, then `carta embed --visual` (README "Visual Embedding") |
| Capture a durable project note | `carta remember` / `carta_remember` → lands in `quirks/` or `notes/` |
| Understand a feature's design | the spec in `superpowers/specs/` + its matching plan in `superpowers/plans/` |
| Verify an install end-to-end | [testing/install-test-guide.md](testing/install-test-guide.md) |

(The overlapping "audit" commands are disambiguated in [../README.md](../README.md) "Which audit command?" and [../AGENTS.md](../AGENTS.md).)

## Docs map

- **[install.md](install.md)** — setup walkthrough (Qdrant, Ollama, embedding/vision/OCR models).
- **[quirks/](quirks/)** — captured quirk notes (surprising system/hardware behavior).
- **notes/** — captured bug-notes / helpful-notes (created on demand by `carta remember`).
- **[superpowers/](superpowers/)** — design specs, implementation plans, and skill docs (see below).
- **[testing/](testing/)** — install/verification guides and the audit tracker.
- **Generated by `/doc-audit`** (not committed; appear after a run):
  - `docs/AUDIT_REPORT.md` — rolling audit findings with stable `AUDIT-NNN` IDs.
  - `docs/BACKLOG/TRIAGE.md` — triage backlog (`DOC-NNN`) sourced from audit runs.

## MCP tools — `carta-mcp` (stdio, `carta/mcp/server.py`)

Claude-initiated tools. Each returns `{"error": "<type>", "detail": "..."}` on failure.

| Tool | Key args | Returns |
|------|----------|---------|
| `carta_search` | `query: str`, `top_k=5`, `scope="repo"\|"shared"\|"global"` | ranked `list[dict]` of chunks (visual hits include image data) |
| `carta_embed` | `scope="all"\|"file"\|"stale"`, `path=None`, `force=False` | `{"status": "ok", ...}` |
| `carta_scan` | — | `{"pending": [...], "drift": [...]}` |
| `carta_remember` | `text: str`, `note_type="helpful-note"\|"quirk"\|"bug-note"`, `title=""`, `tags=None` | saved-note metadata |

## superpowers/ — specs, plans, skills

Per the development flow in [../CLAUDE.md](../CLAUDE.md) ("Development Workflow"): a **spec** in `specs/` captures an approved design; the matching **plan** in `plans/` is its phased implementation. A spec and its plan share a date-slug, e.g.
`specs/2026-06-14-contextual-chunk-headers-design.md` ↔ `plans/2026-06-14-contextual-chunk-headers.md`.

- `specs/` — design specs (`YYYY-MM-DD-<feature>-design.md`).
- `plans/` — implementation plans (same date-slug as their spec).
- `skills/` — `audit-embed.md`, `carta-repair.md`, `carta-workflow.md`.

> Per-doc `status` (shipped / pending / superseded) plus `id` and `related` cross-links
> are being added as YAML frontmatter in **[#48](https://github.com/Ian-q/Carta/issues/48)**.
> Until then, a spec's current status is noted in its own body.
